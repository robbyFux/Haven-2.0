# Quick 260331-u38: Fix DetectionZone Not Persisting on Save

**One-liner:** Fixed race condition where `onBack()` fired before `DataStore.edit` completed, causing zones to be silently discarded.

## Problem

`ZoneEditorViewModel.saveZone()` launched a fire-and-forget coroutine via `viewModelScope.launch`, then `ZoneEditorScreen` immediately called `onBack()` synchronously. Back-navigation cleared the ViewModel, cancelling `viewModelScope` and killing the in-flight DataStore write before it could complete.

## Fix

Replaced `saveZone(zone)` and `clearZone()` with `saveZoneAndBack(zone, onBack)` and `clearZoneAndBack(onBack)`. Each function launches a coroutine that:
1. Awaits `settingsRepository.setDetectionZone(...)` (suspending DataStore write)
2. Calls `onBack()` via `withContext(Dispatchers.Main)` only after the write succeeds

Both landscape and portrait call sites in `ZoneEditorScreen` updated accordingly. The stale inline `onBack()` and `viewModel.clearZone()` / `viewModel.saveZone()` calls removed.
