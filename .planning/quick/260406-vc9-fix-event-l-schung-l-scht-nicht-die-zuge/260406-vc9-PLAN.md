<objective>
Fix event deletion to also remove associated media files from disk.

Currently `EventRepository.deleteEvent()` and `discardTriggersSince()` only remove database rows. The Room CASCADE deletes `event_triggers` but never touches the filesystem. Encrypted video clips (`clip_*.mp4.enc`) and any other `mediaPath` files accumulate indefinitely.

Root cause: No DAO query to collect `mediaPath` values before deletion, and no file-deletion step in either repository method.
</objective>

**EventTriggerDao.kt** — add two new suspend queries:

```kotlin
/** Returns all non-null media paths for triggers belonging to [eventId]. */
@Query("SELECT mediaPath FROM event_triggers WHERE eventId = :eventId AND mediaPath IS NOT NULL")
suspend fun getMediaPathsByEvent(eventId: Long): List<String>

/** Returns all non-null media paths for triggers in [eventId] at or after [cutoffMs]. */
@Query("SELECT mediaPath FROM event_triggers WHERE eventId = :eventId AND timestamp >= :cutoffMs AND mediaPath IS NOT NULL")
suspend fun getMediaPathsSince(eventId: Long, cutoffMs: Long): List<String>
```

**EventRepository.kt** — update both deletion methods to delete files before rows:

`deleteEvent()`:
```kotlin
suspend fun deleteEvent(eventId: Long) {
    val paths = triggerDao.getMediaPathsByEvent(eventId)
    paths.forEach { path -> runCatching { java.io.File(path).delete() } }
    eventDao.deleteById(eventId)
    // Room CASCADE deletes the event_triggers rows automatically
}
```

`discardTriggersSince()`:
```kotlin
suspend fun discardTriggersSince(eventId: Long, cutoffMs: Long) {
    val paths = triggerDao.getMediaPathsSince(eventId, cutoffMs)
    paths.forEach { path -> runCatching { java.io.File(path).delete() } }
    triggerDao.deleteSince(eventId, cutoffMs)
}
```

Use `runCatching { File(path).delete() }` for each file — silent no-op if file is already absent (race-condition safe). No additional imports needed beyond `java.io.File` which is already available in the JVM stdlib.

Do NOT modify `TimelineViewModel` or `EventDetailViewModel` — they already call `repository.deleteEvent()` which will now handle files automatically.
