# Quick Task 260406-070: SignalIntentChannel — P2 Signal App Fallback

**One-liner:** P2 fallback alert channel via Android Intent to local Signal app: SignalIntentChannel implements HavenAlertChannel with isEnabled gated on recipientNumber, wired end-to-end from DataStore through ViewModel, Settings UI, and MonitorService.

## What Was Done

Added `SignalIntentChannel` as the third alert channel in the NotificationEngine. Unlike `SignalRestChannel` (which requires a self-hosted signal-cli REST API server), `SignalIntentChannel` sends alerts by firing an `Intent.ACTION_SEND` to the locally installed Signal app (`org.thoughtcrime.securesms`), enabling users without a server to still receive Signal notifications.

## Decisions Made

1. **Heartbeat disabled:** `sendHeartbeat()` returns `Result.success(Unit)` without dispatching any intent. Repeated intent-launches would open the Signal compose screen on an unattended device, which is disruptive for a surveillance context.

2. **Attachment silently dropped:** `Intent.ACTION_SEND` with `type = "text/plain"` cannot carry binary JPEG data alongside a message. Attachment parameter is ignored — the alert text-only message is sufficient for the fallback use case.

3. **EXTRA_EMAIL for recipient pre-fill:** Signal does not have a public URI scheme for phone-number pre-fill in all versions. `Intent.EXTRA_EMAIL` is used as best-effort — some Signal versions honour it, others don't. The recipient field is still stored in DataStore for UI display and future improvements.
