<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser → Django views | Untrusted event_ids list submitted via bulk POST; must be validated against user ownership |
| Django views → PostgreSQL | Bulk update/delete operations; must be scoped to authenticated user's events only |
| Alpine.js state → HTMX POST | Client-side selected array drives form submission; server must re-validate ownership regardless of client state |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-08-03 | Tampering | bulk_archive / bulk_delete / bulk_unarchive views | mitigate | Always filter by user_id=request.user.id before update/delete: `Event.objects.filter(user_id=request.user.id, id__in=event_ids)` — attacker-supplied IDs for other users' events are silently excluded |
| T-08-04 | Tampering | CSRF on bulk POST forms | mitigate | {% csrf_token %} in hidden forms; HTMX global CSRF config already in base.html (confirmed by existing hx-post revoke button working) |
| T-08-05 | Elevation of Privilege | Mass deletion via bulk_delete | mitigate | Ownership queryset filter before delete; empty event_ids list (no selection) is a no-op |
| T-08-06 | Information Disclosure | is_archived field in Django model | accept | Boolean field adds no new sensitive data; archived events remain owned by user and inaccessible to other users via existing user_id ownership checks |
| T-08-SC | Tampering | pip/npm installs | accept | No new packages installed in this plan |
</threat_model>
