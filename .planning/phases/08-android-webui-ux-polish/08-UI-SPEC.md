## Component Inventory

### Android — Components Modified or Added in This Phase

#### HorizontalDivider (new usage)
```
HorizontalDivider(modifier = Modifier.padding(vertical = 8.dp))
```
- Import: `androidx.compose.material3.HorizontalDivider`
- Color: default (resolves to `MaterialTheme.colorScheme.outline`)
- Thickness: default (1dp)
- Placement rule: inserted between each pair of adjacent `SettingsSection` composables inside `CategoryCard`, skipping the last one. Pseudocode:
  ```
  sections.forEachIndexed { i, section ->
      section()
      if (i < sections.lastIndex) HorizontalDivider(Modifier.padding(vertical = 8.dp))
  }
  ```
  Since `SettingsSection` items are currently placed as direct calls (not a list), the divider is inserted literally between each `SettingsSection { }` block in `CategoryCard` bodies that have 2+ sections.

#### SettingsSection (existing — no change to composable itself)
- Title padding: `top = 16.dp, bottom = 4.dp` (already present, do not change)
- The divider replaces the implicit vertical gap that currently exists between sections; the existing `Spacer(Modifier.height(0.dp))` at top of screen column remains unchanged.

### WebUI — Components Modified or Added in This Phase

#### Status Dropdown (new filter control)
- Location: event filter bar (`list.html`), same `<form id="filter-form">` container
- Pattern: identical structure to existing Device and Type dropdowns
- HTML:
  ```html
  <div class="flex flex-col gap-1">
    <label class="text-xs text-gray-400">Status</label>
    <select name="status"
            class="bg-gray-700 text-gray-100 rounded px-2 py-1 text-sm border border-gray-600 focus:outline-none focus:border-teal-500">
      <option value="active" {% if request.GET.status == "active" or not request.GET.status %}selected{% endif %}>Active</option>
      <option value="archived" {% if request.GET.status == "archived" %}selected{% endif %}>Archived</option>
      <option value="all" {% if request.GET.status == "all" %}selected{% endif %}>All</option>
    </select>
  </div>
  ```
- Default selection: "Active" (no `status` param = active events only — D-01)
- Trigger: `hx-trigger="change"` already on parent form — no additional wiring needed

#### Bulk Checkbox Column (new)
- Location: `event_table.html` thead + `event_row.html` first `<td>`
- Header checkbox: "Select all" via Alpine.js `x-model` toggle
- Row checkbox: `<input type="checkbox" name="event_ids" value="{{ event.id }}">` managed by Alpine.js parent state
- Alpine.js pattern:
  ```html
  <div x-data="{ selected: [], selectAll: false }"
       @change="selectAll = selected.length === totalCount">
  ```
- Checkbox styling: `class="rounded border-gray-600 bg-gray-700 text-teal-600 focus:ring-teal-500"`
- Column header: `<th class="px-4 py-3 w-10">` — 40px fixed width, no label text, contains select-all checkbox

#### Bulk Action Bar (new, conditionally visible)
- Shown when `selected.length > 0` via `x-show="selected.length > 0"`
- Position: between filter form and event table (`#event-table`)
- Styling: `class="bg-gray-800 rounded-lg px-4 py-2 flex items-center gap-3 text-sm"`
- Content: `<span x-text="selected.length + ' selected'" class="text-gray-300"></span>` + Archive Events button + Delete Events button
- Archive Events button: `class="bg-teal-700 hover:bg-teal-600 text-white rounded px-3 py-1 transition-colors"` — opens Alpine.js confirmation modal
- Delete Events button: `class="bg-red-800/60 hover:bg-red-700/60 text-red-300 rounded px-3 py-1 transition-colors"` — opens Alpine.js confirmation modal

#### Bulk Confirmation Modal (new)
- Trigger: clicking Archive Events or Delete Events in bulk action bar
- Pattern: Alpine.js `x-show` overlay — consistent with D-03
- Structure:
  ```html
  <div x-show="showConfirmModal" x-cloak
       class="fixed inset-0 bg-black/60 flex items-center justify-center z-50">
    <div class="bg-gray-800 rounded-lg border border-gray-700 p-6 max-w-sm w-full mx-4 space-y-4">
      <h2 class="text-lg font-bold text-gray-100" x-text="modalTitle"></h2>
      <p class="text-sm text-gray-400" x-text="modalBody"></p>
      <div class="flex justify-end gap-3">
        <button @click="showConfirmModal = false"
                class="text-gray-400 hover:text-gray-200 px-3 py-1 text-sm border border-gray-600 rounded transition-colors">
          Cancel
        </button>
        <button @click="confirmBulkAction()"
                class="px-3 py-1 text-sm rounded transition-colors"
                :class="pendingAction === 'delete' ? 'bg-red-700 hover:bg-red-600 text-white' : 'bg-teal-600 hover:bg-teal-500 text-white'">
          Confirm
        </button>
      </div>
    </div>
  </div>
  ```
- `modalTitle` and `modalBody` are set dynamically before `showConfirmModal = true`
- Modal backdrop: `bg-black/60` (60% opacity black) — dark overlay on dark theme

#### Delete Button for Revoked Devices (new)
- Location: `device_row.html`, in the `{% else %}` branch (currently shows `—` for revoked devices)
- Pattern: identical to existing Revoke button — `hx-confirm` browser native dialog (D-08)
- HTML (replaces the `<span class="text-xs text-gray-600">—</span>`):
  ```html
  <button
    hx-post="{% url 'devices:device_delete' device.id %}"
    hx-target="#device-{{ device.id }}"
    hx-swap="outerHTML"
    hx-confirm="Delete this device permanently?"
    class="text-xs px-3 py-1 rounded bg-red-900/60 text-red-400 hover:bg-red-800/60 transition-colors"
  >
    Delete
  </button>
  ```
- Swap target: `#device-{{ device.id }}` — same as revoke, removes the `<tr>` entirely by returning empty string or `hx-swap="delete"`
- Note: revoke response returns the updated row; delete response should return empty to remove the row, or the view targets the `<tr>` and the response swaps with nothing

#### Admin SMTP Settings Page (new)
- Route: `admin_panel/settings/` → new template `admin_panel/templates/admin_panel/smtp_settings.html`
- Page structure: mirrors `ai_settings.html` (back link, page heading, description paragraph, form card)
- Focal point: page heading (`<h1>`) draws the eye first, followed by the form card below.
- Form card: `class="bg-gray-800 rounded-lg border border-gray-700 p-6"` — same as AI settings
- HTMX inline swap: `hx-post` → `hx-target="#smtp-settings-form"` → `hx-swap="innerHTML"` — same as AI settings pattern
- Navigation entry: add "SMTP Settings" link on admin dashboard page

## Interaction Contracts

### Android — HorizontalDivider

- No interaction. Static visual separator.
- Accessibility: decorative element, no content description needed (`contentDescription = null` is default for `HorizontalDivider`).

### WebUI — Select All Checkbox

- Clicking "Select all" header checkbox: sets all visible row checkboxes to checked state (Alpine.js `x-model` sync).
- If any row checkbox is manually unchecked: "Select all" unchecks automatically.
- If all row checkboxes are checked manually: "Select all" checks automatically.
- Bulk action bar appears/disappears based on `selected.length > 0` — transition: `x-transition` fade (Alpine default or explicit `x-transition:enter="transition ease-out duration-100"`).

### WebUI — Bulk Archive Flow

1. User selects 1+ checkboxes.
2. User clicks "Archive Events" in bulk action bar.
3. Alpine.js sets `modalTitle`, `modalBody`, `pendingAction = 'archive'`, opens modal.
4. User clicks "Confirm Archive": HTMX POST to `events:bulk_archive` with `event_ids[]`, targets `#event-table`, swaps innerHTML with refreshed table partial.
5. Modal closes, selected state resets to `[]`.
6. Success flash message rendered in refreshed partial (or via Django messages framework outside the swap zone).

### WebUI — Bulk Delete Flow

1. User selects 1+ checkboxes.
2. User clicks "Delete Events" in bulk action bar.
3. Alpine.js sets `modalTitle`, `modalBody`, `pendingAction = 'delete'`, opens modal.
4. User clicks "Confirm Delete": HTMX POST to `events:bulk_delete` with `event_ids[]`, targets `#event-table`, swaps innerHTML.
5. Modal closes, selected state resets.
6. Confirm button uses red styling (`bg-red-700`) when `pendingAction === 'delete'`.

### WebUI — Revoked Device Delete Flow

1. Revoked device row shows "Delete" button (red styling).
2. User clicks Delete: browser `hx-confirm` dialog fires ("Delete this device permanently?").
3. User clicks OK: HTMX POST fires, `<tr>` is removed via `hx-swap="outerHTML"` returning empty response (or `hx-swap="delete"`).
4. No page reload.

### WebUI — SMTP Test Email Flow

1. User fills SMTP form fields and clicks "Send Test Email".
2. Button is disabled and shows spinner or "Sending…" text while request is in flight (`hx-indicator` or Alpine `x-bind:disabled`).
3. Success or failure flash renders inside the form card swap zone.

## Android Comment Standardization Contract

This section defines the non-visual contract for the code documentation work (not user-visible, but governs executor decisions).

### Scope

| File | Work |
|------|------|
| `SensorFusionEngine.kt` | Translate German inline comments to English; add WHY explanations for Complementary Filter algorithm (alpha=0.7 choice, fusion math) |

| `PerceptualHashDetector.kt` | Translate; add WHY for DCT-based perceptual hashing, bit-comparison strategy |
| `HavenObjectDetector.kt` | Translate; add WHY for EfficientDet Lite 0 model choice, score threshold |
| `MonitorService.kt` | Translate German inline comments; no WHY expansion needed |
| `ZoneEditorScreen.kt` | Translate German inline comments; no WHY expansion needed |

### KDoc Rules (from CONTEXT.md discretion)

- Add `@param` only for parameters where the name alone is insufficient (e.g. a `Float alpha` parameter — what does "alpha" represent here?).
- Add `@return` only for non-obvious return values (e.g. `Long` trigger row ID; not for `Unit` or `Boolean` toggle returns).
- Do NOT add boilerplate `@param` tags for self-documenting parameters (e.g. `enabled: Boolean`).
- KDoc comment style: `/** … */` block, not `//` inline on the function signature line.

### Comment Style Rules

- Language: English only. All existing German inline comments are translated.
- Style: sentence fragments are acceptable for inline comments (no trailing period required).
- WHY format: explain the reason the value/approach was chosen, not what the code does. Example: `// alpha=0.7 retains 70% gyro contribution — gyro is more accurate short-term but drifts; accel corrects long-term drift`

## Accessibility Notes

### Android

- `HorizontalDivider` is decorative — no `contentDescription` needed (Material 3 default behavior).
- All existing touch targets remain ≥ 48dp (CLAUDE.md §5 rule; no changes to interactive elements except adding dividers).
- `SettingsSection` titles already use `MaterialTheme.typography.titleSmall` — legible contrast on `surfaceVariant` background.

### WebUI

- Checkboxes must have associated labels or `aria-label`. Use `aria-label="Select event {{ event.id }}"` on row checkboxes; `aria-label="Select all events"` on header checkbox.
- Confirmation modal must trap focus when open. Alpine.js `x-trap` (if alpine-trap plugin is available) or native `autofocus` on the Cancel button.
- `hx-confirm` dialogs are native browser dialogs — accessible by default.
- Color is not the only differentiator for status badges (Active/Revoked): text label is always present alongside color.
