<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser -> Django | All user input crosses here (forms, HTMX requests) |
| Django -> PostgreSQL | Django ORM queries against shared database |
| Django -> Filesystem | Video file serving from MEDIA_ROOT |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-01 | Spoofing | Login form | mitigate | Custom auth backend verifies bcrypt; session-based auth via Django middleware |
| T-06-02 | Tampering | CSRF | mitigate | Django CsrfViewMiddleware enabled; HTMX sends X-CSRFToken header via hx-headers on body |
| T-06-03 | Repudiation | Session | mitigate | Django session framework with session.cycle_key() on login |
| T-06-04 | Information Disclosure | Video serving | mitigate | Views check user ownership before serving files; encrypted videos show download-only message |
| T-06-05 | Denial of Service | Login brute force | accept | Rate limiting deferred (can add django-ratelimit later); bcrypt cost factor provides inherent slowdown |
| T-06-06 | Elevation of Privilege | Admin views | mitigate | All admin views check user.is_admin; @login_required + is_admin check decorators |
| T-06-07 | Spoofing | Session hijacking | mitigate | SESSION_COOKIE_SECURE configurable via env; SESSION_COOKIE_HTTPONLY=True (Django default) |
| T-06-08 | Information Disclosure | XSS | mitigate | Django template auto-escaping enabled by default; HTMX renders HTML not JS eval |
| T-06-09 | Tampering | Open redirect | mitigate | LOGIN_REDIRECT_URL set to /events/; next parameter validated by Django's login view |
</threat_model>
