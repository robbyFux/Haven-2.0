<objective>
Two independent improvements that both land in the sensor/storage layer and therefore
belong in a single foundation plan:

1. **SENSOR-10** — Replace the under-sensitive default `Sensitivity.MEDIUM` values with
   the proposed new defaults (accel 2.0×, mic 55 dB, light 40 lux, camera 0.08). `LOW`
   and `HIGH` are adjusted so the three-tier spread stays reasonable.
2. **SENSOR-11 (foundation)** — Add `ExpertThresholds` data class, four
   `floatPreferencesKey` entries in `SettingsRepository`, the
   `expertThresholds: Flow<ExpertThresholds>` exposure, `setExpertThreshold()` and
   `resetExpertThresholds()` operations, and `Sensitivity.effective*` helpers. Wire the
   data class through `MonitorService` into `FusedMotionMonitor`, `LightMonitor`,
   `MicrophoneMonitor` and `CameraAnalyzer` so that a non-null override is honored live.

Purpose: The Expert Settings UI (Plan 03) must have a working backend to bind to. This
plan produces every non-UI artifact Plan 03 depends on, and nothing else.

Output: Monitors consume effective thresholds. `SettingsRepository` has the four new
keys. Default Medium values are fixed. The app still compiles and runs with no UI
changes yet — Expert Settings has no screen in this plan.
</objective>

       ```kotlin
       // ── Expert threshold overrides (SENSOR-11) ───────────────────────────────

       /**
        * Per-sensor custom Medium thresholds. A null field means "use the
        * Sensitivity enum default for that sensor". All four fields null means
        * no customization → all sensors use enum defaults.
        */
       val expertThresholds: Flow<ExpertThresholds> = dataStore.data.map { prefs ->
           ExpertThresholds(
               accelMediumMultiplier = prefs[KEY_EXPERT_ACCEL_MEDIUM],
               micMediumDb           = prefs[KEY_EXPERT_MIC_MEDIUM],
               lightMediumLux        = prefs[KEY_EXPERT_LIGHT_MEDIUM],
               cameraMediumFraction  = prefs[KEY_EXPERT_CAMERA_MEDIUM],
           )
       }

       /**
        * Set or clear a single expert threshold. Passing `value = null` removes
        * the key so the sensor falls back to the Sensitivity enum default.
        * Never write 0f intentionally — that would disable the sensor.
        */
       suspend fun setExpertThreshold(kind: ExpertThresholdKind, value: Float?) {
           val key = when (kind) {
               ExpertThresholdKind.ACCEL  -> KEY_EXPERT_ACCEL_MEDIUM
               ExpertThresholdKind.MIC    -> KEY_EXPERT_MIC_MEDIUM
               ExpertThresholdKind.LIGHT  -> KEY_EXPERT_LIGHT_MEDIUM
               ExpertThresholdKind.CAMERA -> KEY_EXPERT_CAMERA_MEDIUM
           }
           dataStore.edit { prefs ->
               if (value == null) prefs.remove(key) else prefs[key] = value
           }
       }

       /** Remove all four expert threshold keys atomically. */
       suspend fun resetExpertThresholds() {
           dataStore.edit { prefs ->
               prefs.remove(KEY_EXPERT_ACCEL_MEDIUM)
               prefs.remove(KEY_EXPERT_MIC_MEDIUM)
               prefs.remove(KEY_EXPERT_LIGHT_MEDIUM)
               prefs.remove(KEY_EXPERT_CAMERA_MEDIUM)
           }
       }
       ```

    Do NOT add any float-default fallbacks that treat 0.0f as a sentinel. Absent key must map to `null` in the `ExpertThresholds` data class. Do NOT introduce a new `ExpertSettingsRepository` class — use the existing `SettingsRepository` per the Open Questions resolution in RESEARCH.md.
